## Результаты и выводы

### Экспериментальная постановка

Для сравнения использованы 40 вопросов из набора событий 2026 года. Исходный файл содержал 76 вопросов, из которых 56 относились к Wikipedia (`fresh-*`). Выборка из 40 вопросов сформирована случайно с фиксированным `seed=42`.

Сравнивались обычный агентный цикл без фреймворка, LangGraph, LangGraph с критиком, LangGraph с предварительным планированием и сильная модель без инструментов.

Для поиска использовался локальный снимок Wikipedia из 1640 записей. При отсутствии точного запроса в кэше инструмент возвращал пустой результат без обращения к сети. Это устраняет зависимость от внешнего API, но ограничивает полноту поиска.

### Предварительные результаты

| Конфигурация | Accuracy | LLM-вызовов/вопрос | Центов/вопрос |
|---|---:|---:|---:|
| Голый цикл, GPT-4o mini | 45,0% | 4,05 | 0,02378 |
| LangGraph, GPT-4o mini | 45,0% | н/д | н/д |
| LangGraph + критик | 47,5% | 8,28 | 0,05033 |
| План + LangGraph | 12,5% | 5,60 | 0,03697 |

Значения accuracy получены автоматическим оценщиком до завершения ручной проверки. Стоимость LangGraph не восстановлена из сохранённых HTTP-журналов, поэтому обозначена как н/д.

### Вывод 1. Критик не дал убедительного выигрыша относительно затрат

Добавление критика повысило предварительную точность с 45,0% до 47,5%. На 40 общих вопросах критик исправил три ответа, но два ранее правильных ответа стали неправильными.

Средняя стоимость конфигурации с критиком составила 0,05033 цента на вопрос, а среднее количество вызовов модели — 8,28.

Следовательно, в текущей реализации дополнительная проверка не продемонстрировала достаточного прироста качества, чтобы однозначно оправдать вычислительные расходы. При этом критик проверяет подтверждение ответа найденными материалами, а не совпадение с эталоном.

### Вывод 2. Предварительное планирование не улучшило качество

Конфигурация с отдельным построением плана правильно ответила на 5 из 40 вопросов (12,5%). Средняя стоимость составила 0,03697 цента на вопрос.

Наличие предварительного плана само по себе не обеспечивает успешное извлечение фактов: качество зависит от доступности релевантных источников и от того, насколько агент следует плану.

В данном эксперименте планирование оказалось неэффективным. Этот результат относится к реализованному промпту и агентному циклу, а не ко всем подходам к планированию.

### Вывод 3. Доступ к источникам критичен для вопросов о свежих событиях

Сильная модель Sonnet без инструментов не дала ни одного ответа, засчитанного правильным из 40. Такой результат согласуется с характером датасета, содержащего вопросы о событиях 2026 года, для которых необходим доступ к актуальным источникам.

При этом использование локального снимка Wikipedia ограничивает поиск: запрос, отсутствующий в кэше, не может получить новый документ.

### Вывод 4. Накладные расходы фреймворка зависят от сериализации и схем инструментов

В последнем контрольном тесте на вопросе «What is 2 + 2?» обе реализации ответили `4`.

Размер первого HTTP-запроса составил 1015 байт для голого цикла и 882 байта для LangGraph; количество входных токенов — 168 и 136 соответственно. Побайтового совпадения не было.

Различия включали сериализацию сообщений и схем инструментов. Поэтому их нельзя интерпретировать как универсальную стоимость фреймворка: необходимы одинаковые схемы, промпты и параметры для изолированного измерения накладных расходов.

### Ограничения эксперимента

- Размер выборки составляет 40 вопросов, поэтому небольшие различия в accuracy не позволяют делать статистически уверенные выводы.
- Автоматическая проверка не полностью учитывает эквивалентные формы дат и другие семантически совпадающие ответы.
- Часть результатов восстановлена из JSONL без полной истории HTTP-вызовов; соответствующие стоимостные показатели нельзя считать измеренными.
- Wikipedia использовалась в режиме точного локального кэша, что ограничивает полноту извлечения.
- Перед окончательной оценкой требуется ручная проверка не менее десяти автоматически неправильных ответов для выбранных конфигураций.

### Итог

**На текущем наборе задач усложнение агентной архитектуры само по себе не гарантировало улучшения качества.** Критик дал лишь небольшой прирост правильных ответов при заметно больших расходах, а предварительное планирование существенно снизило качество. Основными факторами оказались доступность подходящих источников, управление числом агентных шагов и корректность оценки ответов.
